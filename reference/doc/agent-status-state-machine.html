总览

内核不解析平台词汇。Claude 和 Codex 的差异全部被挡在兼容层，状态归约只认统一事件。

兼容层

Claude 的 hook 事件名、Codex 的 rollout JSON 会先变成 AgentEvent，其中最重要的字段是 kind。

  • 内核不认 Stop、task_complete 或 session_meta。
  • 未知平台事件不猜测，统一落到 Unknown。
  • 事件先按 ID 去重，再按 sequence 丢弃迟到包。

内核归约

核心函数是 reduce_state(previous, event, subagents)。它返回下一状态，以及是否需要在黄灯前先绿闪。

  • Running 与 BackgroundRunning 都投影成对外绿灯。
  • WaitingForPrompt 与 WaitingForUser 都投影成对外黄灯。
  • 只有主线程正常结束且没有活跃子代理时，才产生绿闪。

状态灯语义

对外阶段只有五种，但 is_flashing 与 remove_at_ms 会改变观看效果。

  • 绿灯常亮：主线程或后台子代理正在执行。
  • 绿闪落黄：主线程一轮正常跑完，等待下一条 prompt。
  • 黄灯常亮：等待用户输入、授权或取消后的下一步。
  • 红灯：错误。
  • 绿闪移除：会话确认结束。
绿常亮

Running / BackgroundRunning

主线程执行中，或主线程已停但子代理仍在后台运行。

绿闪落黄

TurnFinished

主线程正常完成一轮，且没有活跃子代理。绿闪保留一段时间后进入黄灯常亮。

黄常亮

WaitingForPrompt / WaitingForUser

等待下一条 prompt，或正在等待授权、elicitation、用户输入。

红灯

Failed

本轮或会话发生错误。迟到子代理事件只能刷新存活时间，不能把红灯复活成绿灯。

绿闪移除

Completed

会话非错误结束。绿闪到期后移除，不落成长期黄灯。

状态表

私有状态比对外阶段多一层，是为了区分“主线程在跑”和“主线程停了但子代理还在跑”。

内部状态 含义 对外投影 灯色 / 闪烁 自然退出
Running主线程执行中 工具调用、生成中、会话启动等主线程活动。 Running 绿灯常亮，不闪。 转入结束、等待、失败、完成；无新事件时按 running timeout 或进程死亡清理。
WaitingForPrompt等下一句 一轮正常完成，对话未结束，等待用户下一条 prompt。 Waiting 通常在 TurnFinished 后先绿闪，再落成黄常亮。 同 provider 下一次主线程运行开始时清理旧等待；另有 30 分钟 failsafe。
WaitingForUser等人操作 权限请求、elicitation、等待用户补充，以及部分用户取消后的等待语义。 Waiting 黄常亮，不闪。子代理事件也不能覆盖它。 下一次主线程运行、会话结束、失败或 30 分钟 failsafe。
BackgroundRunning后台子代理 主线程一轮已停，但活跃子代理集合非空。 Running 绿灯常亮，不闪。 最后一个子代理停止后直接进入 WaitingForPrompt；会话完成或失败也会结束它。
Completed结束并移除 会话确认非错误结束。 Completed 绿闪，随后移除。 remove_at_ms 到期移除；到期前拒绝迟到事件复活。
Failed错误 本轮或会话发生错误。 Error 红灯，不闪。 可被新的主线程事件改写到新语义；迟到子代理事件不会覆盖它。
Unknown保守态 无法识别或冷启动，没有足够信息主动转灯。 Unknown 保持上一状态，不主动驱动灯色。 Error / Unknown 类快照有 60 秒短超时；进程死亡也会移除。

from_phase() 只在内存里缺少私有状态时用于回推；它无法恢复 BackgroundRunning，会把该细分退化成普通 Running。

事件表

事件先决定状态，再决定是否闪烁。agent_id 是否存在，是子代理语义的门槛。

AgentEventKind 来源含义 如何驱动状态 agent_id 绿闪
Running 执行中：会话启动、工具调用、生成中、用户提交 prompt。 主线程事件直接进入 Running；子代理事件只在上一状态为 WaitingForPrompt 时进入 BackgroundRunning。 决定分支。带 agent_id 时还会加入活跃子代理集合。 否。
TurnFinished 一轮正常结束，但对话没结束。Claude 的 Stop、Codex 无错误的 task_complete。 WaitingForUser 保持不变；无子代理则 WaitingForPrompt；有子代理则 BackgroundRunning。 主线程事件通常没有；带 agent_id 时不产生停止绿闪。 仅当主线程事件且最终落 WaitingForPrompt。
WaitingForUser 权限、elicitation、用户中断后等待下一条指令。 直接进入 WaitingForUser，优先级最高。 不靠该字段判定；它是主线程级等待语义。 否。
SessionFinished 会话确认结束。 进入 Completed，清空活跃子代理集合。 否。 是，绿闪后移除。
SubagentStarted 子代理开始。它与主会话共用 session_id，只用 agent_id 区分。 先加入活跃集合；主线程运行或等待用户时保持原状态；等待 prompt、后台运行、未知时进入 BackgroundRunning。 必须带 agent_id 才有子代理语义。 否。
SubagentStopped 某个子代理结束。 先从活跃集合移除；若仍为 BackgroundRunning 且集合清空，则进入 WaitingForPrompt。 必须带 agent_id。 否。最后一个结束也不重新绿闪。
Failed 本轮或会话出错。 进入 Failed，清空活跃子代理集合。 不是子代理专属事件。 否。
Unknown 无法识别的事件或平台语义缺口。 保持上一状态，不主动改变灯色。 不参与子代理集合规则。 否。

优先级：WaitingForUser > 子代理后台运行 > 空闲等待

只走相邻列；回入与终止各自使用独立下轨。

2. 子代理分叉

子代理只把主线程推到后台态；黄灯优先覆盖绿色活动。

3. 状态归约优先级

每帧只投影一个对外相位；下面三项按从左到右判定。

4. 终态守卫

1. WaitingForUser权限、提问、用户输入等待永远压过子代理活动。
2. 子代理后台运行主线程停后，只要集合非空就仍是绿灯。
3. 空闲等待没有主线程活动，也没有活跃子代理，才落回 WaitingForPrompt。

子代理后台运行

这是状态机比灯色多出来的一层，也是 Plan 模式主线程停止后仍然亮绿灯的原因。

集合规则

  • 子代理与主会话共用 session_id；agent_id 是区分主线程和子代理的关键。
  • SubagentStarted 和带 agent_id 的 Running 会把该 id 加入活跃集合。
  • SubagentStopped 会移除该 id。
  • Completed 与 Failed 会清空集合，且后续迟到子代理事件只能刷新 last_seen_at_ms。

主线程结束时的判定

  • 集合为空：进入 WaitingForPrompt，对外黄灯；若事件是主线程 TurnFinished，先绿闪。
  • 集合非空：进入 BackgroundRunning，对外保持绿灯，并清除“等待落黄”的语义。
  • 最后一个子代理结束：直接进入 WaitingForPrompt，不重新绿闪。
  • 若主线程处于 WaitingForUser：子代理开始或结束都不能把黄灯顶回绿色。

为什么子代理事件不等于主线程 Running

主线程 Running 是“当前这盏灯代表的主对话正在执行”。子代理事件只说明“后台还有工作”。两者对外都是绿，但内部收尾完全不同：主线程 Running 之后可以进入等待用户、失败、完成；后台子代理收尾只能落回等待下一条 prompt。

为什么最后一个子代理停止不绿闪

绿闪在本项目里只表示“主线程一轮顺利跑完，准备落黄”。子代理结束只是后台集合清空，不是新的一轮 Stop；如果这里再闪一次，会把系统噪声误读成用户刚完成一次主线程回合。

Codex 子代理说明

当前 Codex rollout 链路没有产生 SubagentStarted / SubagentStopped。 Codex 子线程有独立 rollout，并带 parent_thread_id / source.subagent 等身份信息。 因此这里是“兼容层尚未接入”，不是内核不支持：内核的子代理集合、后台运行语义和优先级规则已经存在。

事件功能说明

每条事件按“发生时会怎样 / 不变量 / 常见误解”展开。默认收起，避免打断快速扫读。

Running 主线程活动直接转绿；子代理活动只在特定后台场景转绿。

发生时会怎样

主线程事件进入 Running。带 agent_id 时先加入活跃集合；若当前是 WaitingForPrompt，则转成 BackgroundRunning。

不变量

主线程 Running 会清理同 provider 的其它 Waiting 会话；子代理 Running 跳过这一步，避免误清其它黄灯。

常见误解

看到绿灯不等于主线程一定在跑，也可能是主线程已停、后台子代理仍在跑。

TurnFinished 一轮完成，不一定是会话完成。

发生时会怎样

若正在等待用户，保持 WaitingForUser；若活跃集合为空，进入 WaitingForPrompt；否则进入 BackgroundRunning。

不变量

只有主线程事件最终落在 WaitingForPrompt 时才产生绿闪。带子代理 id 或无子代理但被等待用户拦截时都不闪。

常见误解

Stop 不是 SessionEnd。它只说明当前轮结束，对话仍然活着。

WaitingForUser 最高优先级等待态，黄灯不闪。

发生时会怎样

直接进入 WaitingForUser。之后任何子代理开始或结束都不会覆盖它。

不变量

直接黄灯不闪。用户中断也被视为等待下一步，不落红灯。

常见误解

“还在等用户”不是“后台没工作”。子代理可能仍在跑，但人的操作优先级更高。

SessionFinished 会话结束，绿闪后移除。

发生时会怎样

进入 Completed，清空该会话的活跃子代理集合。

不变量

移除计时开始后，迟到事件不能复活会话。Claude 的 SessionEnd reason 不用于 success / error 分流。

常见误解

绿闪移除不是“正在运行”；它表示结束确认，只在短时间内可见。

SubagentStarted 把 agent_id 加入集合，最多把空闲等待拉回后台运行。

发生时会怎样

主线程 Running 或 WaitingForUser 时保持原状态；WaitingForPrompt、BackgroundRunning、Unknown 时进入 BackgroundRunning。

不变量

Completed / Failed 不接受子代理事件复活。它不能覆盖 WaitingForUser。

常见误解

它不等于主线程 Running；它通常没有普通 Stop 的绿闪，也不会推进主线程轮次语义。

SubagentStopped 从集合移除；只有集合清空且仍在后台运行态时才落黄。

发生时会怎样

主线程运行或等待用户时保持原状态。若当前是 BackgroundRunning 且集合为空，进入 WaitingForPrompt；否则保持后台运行。

不变量

不产生绿闪。WaitingForPrompt / Unknown 下不会退化成额外的等待态。

常见误解

最后一个子代理结束也不需要再走一次 Stop 动画，直接黄灯才是正确语义。

Failed 红灯终态，清空子代理集合。

发生时会怎样

进入 Failed，清空集合。之后带 agent_id 的事件只刷新 last_seen_at_ms，不会改变状态。

不变量

红灯不闪。迟到子代理事件不能覆盖错误语义。

常见误解

用户主动中断不一定红色。Codex 的 turn_aborted 是黄灯等待，不是接口错误。

Unknown 宁可少动灯，也不猜错。

发生时会怎样

reduce_state 直接返回上一状态，输出灯色不变。

不变量

不会主动转绿、黄、红，也不会产生闪烁。

常见误解

Unknown 不是“未知灯态”总是显示成灰灯。它首先意味着“这条事件不提供转灯信息”。
