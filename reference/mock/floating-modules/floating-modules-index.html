主窗口「组件选择」三套方案

悬浮窗已经改成模块化外壳：组件同级共享同一块窗口，窗口格子数 = 各组件需求之和（夹在默认 4 格与该形态上限之间）， 各组件按需求比例分槽 —— 横条左右并排、竖条 / 方形上下堆叠。下面三套方案只差「主窗口里怎么挑组件」。

方案 A · 列表开关改动最小

一行一个组件：图标 + 名称 + 一句话说明 + 格数，右侧拖拽手柄与开关。

  • 和现有设置卡片同款，落地最快，用户零学习成本
  • 组件多了也能靠滚动 + 排序撑住，适合「设置」这种低频页面
打开 →

方案 B · 卡片画廊最好逛

每个组件一张卡，卡里先画出它在悬浮窗里的样子，开着的那张带翠绿描边。

  • 「这个组件长什么样」一眼可见，适合以后组件变多、陌生人第一次配置
  • 卡片占地方，超过 6–8 个组件就要翻页或折叠
打开 →

方案 C · 列表 + 三形态实时预览最直观

左侧勾选与排序，右侧实时画出方形 / 横条 / 竖条三种形态，标出总格数与每个组件分到的位置。

  • 直接说明「多一个组件窗口会长多大、谁在前谁在后」，贴边换形的行为不用猜
  • 信息密度最高，实现量也最大（预览要跟着配置实时重算）

三套方案里的开关都能点，状态行会同步「已启用数量 / 窗口格子需求」。
