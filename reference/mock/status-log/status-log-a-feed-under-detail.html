按你的批注改的：左列一个字都不动，日志不再是版面里独立的一块，而是右列「记录详情」在「最近提问」下面多出来的 一个条目 —— 一行结论 + 最近两行摘要（整块约 127px），行尾的「导出本会话」旁边那个图标按钮点开 整窗浮层才看完整链路。这套交互与 ScriptEditor / ScriptEditorModal （信息卡拓展里那个代码编辑视图）完全一样，你不用重新学：内嵌小块 + 角标展开 + fixed inset-0 实色面板 + 标题栏「完成」/ Esc 退出。 回决策页（关闭态三种画法 + 已拍定规格）。

  • 代价：看完整链路要多点一次「展开」；浮层期间看不到左列选中项和详情（脚本编辑器本来也是这个取舍）。
  • 实现口径：内嵌小块只查 key = 选中会话 的最近 3 行（一次 get_status_log({key, limit:3})，第一条做结论行、后两行做摘要）；浮层是左右两栏主从 —— 左栏拉本会话全部流水（新→旧），点一行在右栏看那条记录的完整信息（LogEntry 全字段 + detail + 磁盘上那一行 JSONL 原文 + 同 trace_id 的其它行）。不再有「按这一条信号过滤」这个控件，也不在行下面就地展开。浮层外壳照 .jse-modal 那套 CSS 类（main.css:1149 起：实色铺满、44px 标题栏、「完成」+ Esc）。⚠️ 但 ScriptEditorModal.vue 没有 slot —— 模板里写死了 ScriptEditorFrame 和 aria-label，那个组件复用不了；要么给它加一个默认 slot（动到正在用的脚本编辑器），要么新写一个约 30 行的 overlay 组件共用同一套类名。这条要你先定。
  • 导出口子两处、不是重复入口：条目行上的「导出本会话」= query.key = 选中会话；浮层里的「导出当前条件」= 当下过滤条件（环节 / 只看被拒 / 暂停跟随期间）。同一个 export_status_log({ path, query })，只是范围不同。
  • 左列会话卡片本轮改成定高 + 顶对齐：min-height: 52px（实测渲染 60px）、两行内容 align-content: start、提问一律一行省略号收尾（真实现里把 .sr-list__prompt 的 line-clamp-2 换成单行）。⚠️ 两处坑：行内网格与列表自己都要写 align-content: start —— 列表是 flex 子项会被拉满卡高，默认 stretch 会把富余摊给每一行，实测能把行撑到 105px、看着就像内容被拉开。
