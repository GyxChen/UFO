悬浮窗「没有 Agent 时」· 四套方案

现状：一个 CLI 会话都没有时，窗口里什么都不画 —— 一块空毛玻璃方块。用户看到它的第一反应是 「是不是挂了」，而不是「现在没在跑」。而且空态出现的频率不低：开机后、跑完收工后、只在写文档的下午， 屏幕上都挂着这块空窗。
空态时的窗口尺寸按实测口径渲染：只有 agent 启用时是 45×45（方形 / 横条 / 竖条都一样， agent 需求恒 ≥1 格）、贴角 90×45、与待办同级时整窗 135×45 （agent 占 1/3）。下面每套都给了这四种场景，1:1 真实尺寸 + 3× 放大。

方案 A · 待机暗灯推荐最克制

正中一个 10px 的空心圆（1.5px 描边、白 26%），不改现有灯点的尺寸语言 —— 亮起来是实心彩点， 闲下来就是同一个圆的空心版，像设备的待机指示灯。零动效、零小字，39px 里也一眼看得清「窗还活着」。

方案 C · 呼吸暗点有动效

一个 7px 的灰点，4.5 秒一次极慢的明暗呼吸（16% ↔ 42%）。它想表达「在线，在等 agent」， 和「绿闪 = 刚做完一轮」是两种时间尺度。⚠️ 风险也在这：悬浮窗是常驻的，一直有东西在动容易分神， 而且用户可能把它读成「有活儿在跑」。本页已按 prefers-reduced-motion 做了静态兜底。

方案 D · 待机文字
