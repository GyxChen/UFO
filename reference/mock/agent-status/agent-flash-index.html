状态灯「完成闪烁」· 四套加强方案

现在的闪烁是 1s ease-in-out：不透明度 1 → 0.35、同时缩到 0.78 倍，然后循环。 之所以不显眼，是三个原因叠在一起：
① 它是渐变而不是跳变 —— 眼睛把平滑的明暗当成「呼吸」，只有突然的开关才被当成「事件」； ② 振幅方向错了 —— 暗下去 65%、并且是缩小，而人对「变大 / 变亮」远比对「变小 / 变暗」敏感； ③ 只有灯点自己在变 —— 右下角那块平台徽章不动，背景上也没有任何新东西出现，整格几乎没有变化。
下面四套都在「灯点 / 格子」这一个小范围内动手：不改变位置、不撑破格子（真实槽位是 overflow: hidden，放大超出会被切成直边）。每格里第二个灯是常亮对照组， 方便直接比。闪烁只出现在两种完成态（Stop / SessionEnd），其余灯态不闪。

本机开启了系统级「减少动态效果」：下面所有预览都停在静止态 —— 这正是实现里的行为（四套都会停下动画， 改用一圈静态描边把「刚完成」这件事留在画面上），不是页面坏了。

方案 A · 硬切闪改动最小

把 ease-in-out 换成 steps(1, end)：明暗跳变，不再有中间过渡； 同时去掉缩放（只留开关灯）。周期 0.9s、亮暗各占一半 —— 这是老式设备指示灯的经典语汇， 人眼对「跳变」的敏感度比「渐变」高一个量级，而改动只有两行。

方案 B · 脉冲环最不像报警

灯点保持常亮不再闪，改由它向外甩一圈同色光环（1.4s 一次、边扩大边淡出，像定位图标的 ping）。 被看见的是「新东西出现 + 面积变化」，这在余光里比明暗变化更容易捕捉；因为灯点本身稳定， 它读起来是「响了一下」而不是「出事在闪」。环的余量按灯点（限制轴的 80%）算到 1.1 倍，不会顶破格子。

方案 C · 加大振幅已采用只改数字

保持「渐变呼吸」的形态，但把幅度拉满、节奏加快：谷底不透明度 0.35 → 0.12，缩放从 「缩到 0.78」改成「涨到 1.10 再落到 0.82」，周期 1s → 667ms（1.5 倍频）。 改动只是 keyframes 里的几个数字；峰值定在 1.10（不是 1.12）是算过格子余量的上限 —— 灯点占限制轴的 80%，再叠描边与光晕，1.10 刚好不越界。实现里同时补了 prefers-reduced-motion 降级（停动画、保留一圈静态描边）。

方案 D · 整格闪面积最大

三件落地时必须一起做的：
① 补 prefers-reduced-motion：现在这条闪烁没有任何降级（全站其它动画都有）。 四套都要在用户开启「减少动态效果」时停下来 —— 建议退化成「常亮 + 一圈静态浅描边」，而不是干脆不闪。
② 放大预算按格子算：灯点占限制轴的 80%，四周只剩 10%；加上 1px 白描边与 2px 光晕， 放大到 1.1 倍左右就到格子边了（真实槽位 overflow: hidden，再多会被切成直边）。 格子大小可调（32–96px）时这些倍数与 --floating-cell-scale 一起走，不要写死像素。
③ 别把「闪」用成第二种语义：绿闪 = 一轮完成（Stop → 之后转黄 / SessionEnd → 之后移除）。 黄 / 红 / 常亮绿都不闪，否则「闪 = 需要我注意」就失效了。
另一个方向（不在这四套里）：完成时不是「闪」，而是在灯点上叠一个对勾持续 1–2 秒 —— 语义最明确， 但它改的是「怎么表达完成」，不是「怎么把闪做明显」，要的话单独出方案。
