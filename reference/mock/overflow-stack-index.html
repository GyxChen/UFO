「+N 溢出格」四套方案

现状：一格只放得下这么多灯时，最后一格留白 + 居中 +N。希望改成 「+N 的背景是被折叠的那几盏指示灯堆叠起来」，带层次感，并且悬停这一格能列出被折叠会话的状态。
⚠️ 关键前提：未贴边的方形只有一格（窗口尺寸与格子数无关，多组件时内容是等比压缩）， 所以会话 ≥ 2 时整窗就是这块溢出格 —— 它不是"边角料"，而是常见状态下悬浮窗的**唯一面孔**， 必须自带足够信息（能看出颜色、能看出"后面还有"）。贴角 / 横条 / 竖条才会出现「几盏灯 + 溢出格」并排。

方案 A · 实心错位堆叠最像一叠灯

深色前盘托住 +N，后面沿左上错位叠 2–3 层彩色灯盘，层间压暗边 —— 「这里还压着好几盏」的物理感最强。

  • 层次感来自真实的错位 + 落影，最耐看；前盘深色让数字永远读得清
  • 颜色是"素材"：只能看出叠了什么色，看不出比例

方案 B · 分片环信息量最大

外圈是按状态占比切开的彩环（红 / 黄 / 绿各占多少），后面两圈同色模糊光晕做层次， 中心深盘放 +N。

  • 唯一能读出比例的一套：「5 个里有一盏红的」不悬停就知道
  • 外圈吃完后中心只剩一格边长的 54%，三位数最紧；光晕受槽位裁切限制

方案 C · 微型灯阵语义最直白

被折叠的灯原样缩小沿对角线叠 3 盏（真色、真闪烁），右下角用「平台图标徽章」的位置放 +N。

  • 「这是三盏灯」零解释成本，闪烁状态一并继承
  • 元素最多，格子 ≤ 32px 时三盏小灯会糊成一团，必须降级成一盏 + 数字

方案 D · 涟漪同心灯色最醒目

前面是一盏真正的灯（折叠里最需要注意的那盏，该闪就闪），后面 1–2 圈同心细环按次优先级灯色向外淡出。

  • 45px 下灯色最好读（灯占格 62%），小格子里也不失真
  • 一盏红灯在最前面，容易被误读成"这格对应的会话报错了"

四套共用的部分（不随方案变）

  • 层数 / 灯数上限 = min(折叠数, 3)：3 已经足够表达「一摞」，再多只会把格子涂满。 注意容量满时最后留一格，所以折叠量恒 ≥ 2，不会出现「只有一层堆叠 / 只有一盏小灯」的怪样子。
  • 次序按注意力优先级：红（出错）→ 黄（等你操作）→ 绿（执行中），而不是按会话开始时间 —— 缩小后最需要注意的是"有没有红的"，不是"谁先来的"。
  • 悬停清单：溢出格上报一个合成悬停目标（如 { moduleId, key: '@overflow' }）， 信息卡内容组件改渲染清单：标题「后面还有 N 个会话」+ 红/黄/绿统计 + 每行「灯 + 平台图标 + 阶段 + 提问摘要」。
  • ⚠️ 提示窗是点击穿透窗口（focusable: false + 忽略光标事件）：清单不可交互， 不做行悬停高亮、不靠 title；行数超出时内部滚动（超过 8 行折成「还有 N 个」）。
  • ⚠️ 提示窗默认 300×260（tauri.conf.json），清单要用 tooltip.size 按行数算高度；一行 ≈ 20px + 头部 28px，5 行 ≈ 140px，仍在默认高度内。
  • 缩放：所有写死的设计像素乘 var(--floating-cell-scale, 1) （错位量、暗边、描边、环宽、字号），格子调到 96px 时整块等比放大； @container 里的 32px 阈值不乘倍率（那是绝对可读性阈值）。
  • 降级：槽位矮于 / 窄于 32px（同级组件挤压）时「灯色优先」—— A / B / C / D 各自退到 「一个色块 + 数字」，细节（层、环、小灯）让位。
