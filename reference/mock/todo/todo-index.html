现状 = 三面小旗（红 / 黄 / 蓝）+ 数量，横排或竖排。问题出在未贴边的方形：窗口只有 45×45、 组件真正拿到的槽位约 39×39，三面旗 + 数字排不下，于是数量被降级掉，只剩三面很小的旗子 —— 远看像三个色块，既读不出「哪档几个」，旗形在这个尺寸也认不出来。 下面四套都按真实像素渲染（另有 3× 放大版看清细节），数据统一取 高 2 / 中 1 / 低 3。

方案 A · 数字主导信息最全最克制

去掉旗子字形，数字就是主角：三档各自用语义色上色，数字下方（竖条里是左侧）压一条色条当锚点 （颜色 + 位置双通道，不靠颜色单挑）。39px 里三组「数字 + 色条」横排正好排开，是本方案在方格里最大的优势； 竖条三行等宽、色条排成一条竖线，字号取竖条自己的预算再按 0.8× 收一档（大约 15.5px），整块上下居中。

方案 D · 三行小表列表感

三行「色块 + 数字」上下排，像一张极小的小表：色块代替旗子字形（4×10px 的圆角块比 9px 的旗形干净得多）， 数字是主文本色、优先级只由色块承载。竖条里天然成立，方形里三行也正好放得下 —— 代价是四种形态观感趋同。
